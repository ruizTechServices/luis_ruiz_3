# Soundboard publishing

Go to **Dashboard → Manage sounds** (`/dashboard/soundboard`). The existing verified Gio account is required for both the page and its upload/update API.

1. Add a name, category, and MP3 or standard integer PCM WAV. Files must be at most 3 MB and between 0.05 and 60 seconds; stereo or mono WAV supports 8–96 kHz, 8/16/24/32-bit integer samples.
2. Upload saves a **draft**. Preview its audio in the dashboard.
3. Select **Published** and save to add the pad to the public soundboard immediately. Daily-pick eligibility only applies to published clips.
4. Change the name, category, order or visibility at any time. **Archived** hides the pad and excludes it from daily picks. Republish to restore the same sound link and saved favorites.

Audio URLs themselves are public even while a pad is a draft or archived. The upload form explains this. Upload only clips intended for public sharing. Archiving is not file removal. No file-deletion or replacement operation is offered; each upload uses a UUID path, and all 16 original files remain in the repository byte for byte. New clips use touch/click controls without taking the original pads’ keyboard shortcuts.

The public catalog comes from `public.soundboard_clips`, filtered to `status = 'published'`. The owner can read drafts and archives. Column-level grants prevent rewriting the original IDs, audio paths, shortcuts and durations. New clip inserts default to draft and cannot claim to be originals. The original typed catalog remains the seed and provenance record. If the database request fails, the public page shows an unavailable state with a retry button. It does not resurrect archived originals. An intentionally empty published catalog stays empty.

`POST /api/soundboard` accepts bounded multipart data, verifies the owner and same-origin request, and reserves one of ten upload attempts in a UTC clock hour using a database operation. Invalid attempts count toward the limit. MPEG Layer III validation walks every frame and calculates duration from actual frame headers, supporting variable bitrates. It rejects truncated frames, unsupported formats and unrecognized trailing data. WAV validation checks chunk boundaries and PCM format consistency and calculates duration from samples. After those structural bounds, new MP3 uploads are decoded on the server using the exact pinned `mpg123-decoder@1.0.3` WASM package. Decoder errors, non-finite samples, invalid decoded duration, and output containing only silence are rejected. Some corrupt MP3 bodies are concealed as silence by the decoder without an error, so the silence check is intentional. New MP3 duration comes from decoded PCM samples. PCM WAV data is already represented directly by validated sample bytes. The owner can preview the final saved sound before publishing. Decoding does not transcode or replace encoded audio samples. MP3 ID3 tags and WAV ancillary chunks are removed from **new uploads**. Original archived audio is never processed or rewritten. Some MP3 exports contain extra nonstandard trailing data; re-export those files if the upload validator rejects them.

Uploads use the existing Supabase owner session and the dedicated `soundboard-audio` bucket. No service-role key is used. Public file serving does not grant public file listing, upload, update or deletion. Metadata updates use the last `updated_at` value to reject stale edits from another tab. A failed catalog insert after a successful file upload leaves an unlisted file, logs its UUID path, and shows a retry message; it never publishes a broken pad or overwrites an existing file.

Preferences remain local to each browser. They validate original IDs and UUID-based new IDs, retaining archived favorites so they return when a pad is republished. The visible favorites count includes only currently published clips. Actual new or restarted playback triggers the aggregate analytics callback after `audio.play()` succeeds; pause/resume does not produce a new play event.

Verification: `npm run test:soundboard` covers original asset SHA-256 values, soundboard controls/preferences, MP3 variable-bitrate duration and tag removal, actual decoding of real archived MP3s, rejection of corrupt frame bodies that pass structural checks, WAV metadata removal, malformed/truncated/oversized/overlong audio, and chunked multipart limits. `supabase/tests/soundboard_access.sql` is a rollback-only database role check for draft/archived visibility, owner publication, immutable original file paths, spoofed-role rejection and quota enforcement.
